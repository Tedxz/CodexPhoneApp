验收日期：2026-10-16。分支：`feat/multi-server-targets`。本记录覆盖真实双机器后端、移动网页浏览器夹具及 Mate 90 Pro Max 真机。

最终 `npm run check` 通过格式、152 项测试、TypeScript 和网页构建；其中原生源码测试 34 项。unsigned / signed HAP 均完成真实 ArkTS 编译和打包，最终签名包已覆盖安装。

## HarmonyOS 真机与运行入口

[真机报告](phone-report.json)记录 HarmonyOS 7 / API 26 的实际 UI 验收。测试使用两个独立网关进程和数据目录，均运行在本 Mac，通过 Funnel 443 与临时 8443 访问；主 Server 配置本机和 XZ-CATL SSH 机器，临时 Server 仅配置本机。

- 原有登录自动迁移，无需再次输入凭据；原网关授权及手机安装身份保留。
- 新增、命名并配对临时第二个 Server；两个 Server 共显示三张机器卡片。分别进入第二个 Server 和 SSH 目标，新建页显示各自配置的项目目录。
- 覆盖安装及完整停止/启动 App 后，两个登录与三张卡片恢复；首次进入首页即可更新，无需离开页面再返回。见[重启后双 Server 首页](phone-two-servers-restarted.png)。
- 关闭临时 Server 后，其卡片显示 502 与状态未更新，主 Server 的两台机器仍已连接；恢复临时服务并刷新后，三张卡片恢复连接。见[离线隔离](phone-server-offline.png)。
- 在手机中选择 XZ-CATL、新建测试会话，发送不使用工具或修改文件的指令，收到精确回复 `PHONE_MULTI_REMOTE_OK` 并回到就绪。页面持续显示 Server、机器和远端工作路径。见[手机远程对话](phone-remote-reply.png)。
- 完成后移除手机临时配置、撤销临时网关授权、停止临时网关并移除 Funnel 8443；主 Funnel 443 及已有授权保留。手机最终展示[本机与 XZ-CATL](phone-final-overview.png)。

真机过程中修复两项系统行为差异：Asset Store 不允许批量明文查询，改为分页枚举属性后逐 alias 解密；ArkUI 稳定列表 key 下的嵌套状态需由 `@ObjectLink` 组件订阅，改后首次加载及在线/离线刷新均在真机验证通过。

主入口的匿名请求被拒绝，两台机器的已认证 HTTPS 列表、bootstrap 和 WSS 握手通过，旧本机 API 保持可用，见[公网地址检查](public-gateway-report.json)。[只读诊断](doctor.txt)确认本机和 SSH 的已有共享后端握手、列表查询及 SFTP 探测通过。主服务只监听 `127.0.0.1:8787`，由既有 LaunchAgent 保活。

## 真实双机器后端

[完整报告](real-dual-target-report.json)中的 9 项检查通过。测试使用独立的 `127.0.0.1:18891` 网关与数据目录，接入已有本机和 `xz-catl` SSH 共享后端；最终运行中两端报告版本均为 `0.163.0`。未启动 Codex，未修改已有会话、生产网关或 Codex 全局设置。

- 两目标同时连接，各新建隔离会话；两个独立观察连接分别收到 11、10 条回复增量，并读取到精确预期文本。
- 未配置目标返回 404；错误机器不能读取测试会话或图片；两目标事件不串流。
- [蓝色测试图片](blue-fixture.png)经 SFTP 传到远端后，模型精确回答 `BLUE`；历史返回对应目标的图片 URL。SSH 检查上传目录权限为 `700`，图片为 `600`。
- 远端运行一次 `/bin/sleep 20`，在同一轮次追加指令并停止；第二连接观察到运行、追加文本和中断状态。
- 在独立的只读沙箱会话中，通过远端目标 WebSocket 接受一次 `apply_patch` 审批；批准前文件不存在，批准后隔离文件内容与测试 nonce 一致，本机目标没有收到该审批。
- 重建 TargetManager 与 SSH 隧道后，历史图片 URL 与原图片字节仍一致。

所有本次测试轮次已结束；临时授权已撤销，网关、观察连接和 SSH 隧道已关闭，18891 不再监听。仅保留本次自建验收目录、会话及材料。

## 已知限制与证据范围

本轮真实目标都是 macOS；Linux 路径与传输逻辑已实现但未连接 Linux 真机验收。手机使用 Funnel 域名完成实际操作，但未切换蜂窝网络。两个独立 Server 网关在同一 Mac 上运行，不将此记为跨两台网关主机的网络覆盖。

真实验收首次读取新会话历史时出现一次 `CODEX_-32603`；脚本只重试只读历史查询后恢复，没有重发任务。报告未保存底层 RPC 方法及原始错误消息，不能据此断定具体后端错误原因，也不将该结果记作客户端自动恢复已验收。两次前置脚本运行分别因历史读取及 macOS `/tmp` 规范化为 `/private/tmp` 的断言失败而结束；其自建轮次随后经独立只读检查确认均已完成，临时资源已回收。
